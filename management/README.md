# Atlant CLI

Резервные копии создаются только по явному действию пользователя.
Создание, изменение и удаление записей, сброс счётчиков, смена ключей,
миграция, синхронизация серверов и восстановление не создают автокопий.
При заполнении активного каталога старые копии переносятся без удаления в
`STATE_DIR/backup-archive`; список, восстановление и корзина работают с обоими
каталогами. Архив сохраняет данные, но не освобождает место на диске: срок
хранения и удаление копий контролирует администратор.

Панель, CLI и служебные инструменты в этом каталоге — GPL-3.0-only:
см. LICENSE и LICENSING.md. Лицензия отдельного VPN-ядра этим не меняется.

Независимое управление сервером без Telegram, только стандартная библиотека Python 3.
Код Telegram-бота в этот проект не входит.

На установленном сервере:

```sh
atlant
atlant --lang en
atlant panelurl
atlant panelpassword
atlant logs
atlant help
```

Изменения требуют подтверждения; `--yes` предназначен для доверенных скриптов.
CLI оставлен только для настройки и обслуживания панели: адрес, порт,
логин/пароль, сертификаты, копии настроек панели, язык, лицензия и диагностика.
Пользователи, подключения, подписки, группы, узлы и конфигурация VPN управляются
в веб-панели. Их прямые команды в CLI также отключены. Общий backend Manager
сохранён: веб-панель продолжает использовать прежние операции.

`logs` сначала открывает подменю, а не выводит записи сразу:

1. Показать последние 50 записей VPN.
2. Изменить уровень логирования VPN.
3. Показать путь к журналу.

Журнал VPN хранит systemd-journald. CLI показывает существующие каталоги
`/var/log/journal` / `/run/log/journal` и команду `journalctl` с именем службы
из конфигурации установки. Отдельный текстовый файл Atlant не выдумывается.
Для смены уровня проверяются регистрация службы и перекрывающие флаги.
Сохранение не перезапускает VPN автоматически: применение с разрывом активных
соединений требует отдельного подтверждения. Это единственная настройка
VPN-ядра, оставленная в CLI как явно запрошенная диагностика.

Автоматический сертификат в CLI: для домена вводится только доменное имя,
для IP — локальный порт HTTP-проверки. IP берётся из настроенного внешнего
адреса панели (домен разрешается в публичный IP); определённый адрес
показывается перед подтверждением. При невозможности определения IP операция
останавливается без создания задания. Если домен панели находится за CDN,
перед выпуском проверьте, что показан именно IP вашего VDS.
Job ID генерируется автоматически; email необязателен и не запрашивается,
боевой ACME выбирается автоматически. Согласие с условиями CA и подтверждение
сохранения остаются. Существующий сертификат выбирается номером из списка.

Публичная проверка HTTP-01 всегда использует порт 80. При выборе другого
локального порта агент слушает только `127.0.0.1:ПОРТ`; существующий веб-сервер
должен передавать ему `/.well-known/acme-challenge/` с сохранением Host.
Обработчик общий для всех сертификатов; новое задание и порт сохраняются одной
атомарной операцией с проверкой ревизии, без автоматической резервной копии.

В меню сертификатов пять действий: просмотр, выпуск для домена, выпуск для IP,
редактирование и остановка автоматического продления. Отдельного объединения
сертификатов, управления службой и резервными копиями в этом меню нет.
Существующие адреса панели/подписок и выбранные пользователем сертификаты
автоматически не заменяются. Просмотр показывает их текущие имена без вывода
сырой конфигурации и путей к приватным ключам. Свой сертификат по-прежнему
можно указать в настройках HTTPS панели.

`menu` открывает интерактивное консольное управление. Без команды в обычном
терминале также открывается меню; при перенаправленном stdin выводится справка.
В меню доступны пользователи, просмотр подписок/групп, сертификаты, служба,
журнал и резервные копии. Оно пока не заменяет все прямые команды CLI.
Выбор русского, английского или китайского сохраняется локально;
`--lang` имеет приоритет. Вызов `menu` всегда подтверждает изменения отдельно,
даже при `--yes`.

Сертификаты: `certjobs`, `certjobcreate`, `certjobset`, `certjobdelete`,
`certbackups`, `certrestore`. Формы тех же операций доступны в панели.
Удаление задания останавливает продление, но не отзывает сертификат и не
удаляет ключ. Собственный сертификат панели проверяется `paneltls`;
назначение HTTPS-слушателю пока настраивается отдельно, не через консольную форму.

Для другого компьютера сначала создайте SSH-туннель:

```sh
ssh -N -L 18080:127.0.0.1:8080 root@YOUR_SERVER
python3 management/atlantctl.py --config /private/client.json status
python3 management/atlantctl.py --lang en help
python3 management/atlantctl.py --lang ru status
python3 management/atlantctl.py --lang zh help
```

Закрытый `client.json` (не включать в репозиторий):

```json
{
  "api_url": "http://127.0.0.1:18080",
  "api_key": "YOUR_API_SECRET",
  "state_dir": "/private/atlant-admin-state"
}
```

Файл: `chmod 600`; каталог состояния: `chmod 700`. Клиент отказывается передавать
ключ административного API не-loopback адресу и не следует перенаправлениям.
API нельзя выставлять в интернет. Удалённый CLI не вызывает локальный systemd
сервера. Внутренние операции службы и сохранения конфигурации выполняются
на самом VDS через ограниченный helper; как общие команды CLI они не доступны.

## Данные и резервирование

В разделе «Резервные копии» пользователь отдельно создаёт копию данных VPN,
настроек панели или настроек сертификатов. В CLI доступны `panelbackup` и
`certbackup`. Существующие копии сохранены. Восстановление не создаёт новую
копию автоматически; оно заменяет пользователей и
подписки целиком и может разорвать подключения. Копии содержат ключи доступа;
храните их закрыто, не отправляйте в публичные отчёты. Хранилище ограничено
500 копиями / примерно 256 МиБ; старые копии автоматически не удаляются.

Во внутреннем API панели `configset` меняет только настройки в памяти, `configsave` сохраняет
ограниченный набор параметров в config.json атомарной записью без автокопии;
требуется перезапуск. Аргументы запуска службы могут иметь приоритет над
конфигом. Пути, ключ сервера, версия wire и адрес административного API через
helper не меняются. `tlsset` управляет HTTPS подписок, не REALITY.

Обычные отчёты скрывают секреты. Ссылки доступа, выдаваемые веб-панелью,
нельзя публиковать. Прямые CLI-команды их создания и экспорта удалены из интерфейса.

Подписка может содержать несколько VDS и несколько endpoint. Добавление узла не
устанавливает сервер и не создаёт пользователя на другом VDS. Для него нужно
указать существующие `user` и `pbk`; общего распределённого лимита это не создаёт.
Для сервера с несколькими транспортами нужен один endpoint: транспорт выбирает
клиент. При создании подписки версия wire берётся из ссылки, выданной сервером.
Общий лимит нескольких VDS настраивается отдельными командами quota:
см. docs/GLOBAL_QUOTAS_RU.md. Само добавление endpoint не подключает учёт.

Самостоятельная новая панель находится в management/control. Пока это
разрабатываемый компонент, не готовая замена бота; возможности CLI сохраняются.
CLI поддерживает --lang en/ru/zh. Имена команд и JSON-поля не переводятся.

Проверки:

```sh
python3 -m unittest discover -s management -p 'test_*.py'
```
