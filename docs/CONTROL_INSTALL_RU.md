# Первичная установка самостоятельной Atlant Control

Кандидат установщика: полнофункциональная замена ещё проходит разработку.
Выполняйте первичную установку на копии сервера/изолированном стенде до
приёмки systemd и восстановления на вашем окружении.
Установщик не меняет unit, бинарник, базу, время, firewall или настройки VPN,
не отключает бота и не изменяет x-ui.

## Что делает установленный код

- Собственный процесс панели от системного пользователя `atlant-control`.
- Отдельный root-помощник с проверкой Unix peer UID и ограниченным набором действий.
- Сертификатный агент устанавливается, но не запускается и не обращается к CA
  без явного задания и последующего запуска службы.
- Команда `atlant` открывает меню в терминале; `atlant menu` делает это явно.
- Первоначальный вход — только `127.0.0.1`, отдельный логин/пароль, без открытого
  HTTP в интернете. HTTPS настраивается из панели после выпуска или импорта пары.

## Проверка существующего ядра

Нужны Linux/systemd, root, Python со стандартной библиотекой и нативный
`atlant-cert-agent` для архитектуры сервера. Go на VDS не нужен.

Установщик сверяет настоящий MainPID, argv, cwd и исполняемый файл с unit.
Поддерживается прямой ExecStart одного нативного процесса с литеральными
аргументами. Обёртки, `%`/`$`-подстановки и продолжения команд отклоняются;
их нужно отдельно согласованно мигрировать, а не угадывать конфигурацию.
Соблюдается приоритет Go `-c` / `-config-file` и автоматического поиска.

Административный API должен быть на literal loopback IP с ключом. Его адрес
и ключ извлекаются из реально действующих аргументов/файла; ключ не печатается
в плане и не передаётся в argv. Выполняется только чтение `/api/status`.
Реальный ключ не нужно вводить вручную в JSON или отправлять в чат.

При отдельном флаге запуска `-sni` он перекрывает значение файла:
новый помощник отклоняет сохранение такого поля, интерфейс поясняет ограничение.
Другие разрешённые поля можно сохранять. Изменения в памяти отделены от файла.
Если unit изменён после регистрации, сохранение отклоняется до сверки установки.

## План без установки

Получите SHA-256 **из доверенного релиза**, не от самого скачанного файла как
доказательство подлинности. Хэш проверяет целостность, но не заменяет подпись.
Не запускайте агент от другого проекта или другой архитектуры.

```sh
python3 -I management/install_control.py plan \
  --core-unit atlant_vpn.service \
  --agent /private/release/atlant-cert-agent-linux-amd64 \
  --sha256 EXPECTED_SHA256 --lang ru
```

План не устанавливает пакеты, не создаёт аккаунт и не меняет службы. Чужие
файлы по целевым путям и занятые имена unit приводят к отказу, не перезаписи.
Родительские каталоги должны принадлежать root и не быть доступны группе/всем
на запись. Уже установленный компонент требует отдельной процедуры обновления.

## Первичная установка

```sh
python3 -I management/install_control.py install \
  --core-unit atlant_vpn.service \
  --agent /private/release/atlant-cert-agent-linux-amd64 \
  --sha256 EXPECTED_SHA256 --port 9090 --lang ru
```

Вводятся подтверждение `yes`, логин и пароль с повтором. Пароль не попадает
в аргументы процесса и хранится только как scrypt-хэш. Поддержаны en/ru/zh.
Создаются собственные пути:

| Назначение | Путь |
|---|---|
| root-owned код и агент | `/opt/atlant-control` |
| client.json 0640 и helper.json 0600 | `/etc/atlant-control` |
| приватное состояние панели | `/var/lib/atlant-control` |
| root-состояние и аудит помощника | `/var/lib/atlant-control-helper` |
| приватный журнал установки | `/var/lib/atlant-control-installer` |
| терминальное меню | `/usr/local/bin/atlant` |

Запускаются и включаются только `atlant-control-helper` и `atlant-control`.
Служба агента устанавливается, но не стартует: порт 80 и CA не затрагиваются.
Локальная проверка `/control/health` сверяет уникальный ID установки без пароля
или ключа API. Этот ID не является токеном авторизации.

Первый доступ с компьютера администратора:

```sh
ssh -N -L 9090:127.0.0.1:9090 root@YOUR_SERVER
```

Откройте `http://127.0.0.1:9090`. Защита Host/Origin требует одинакового
порта в адресной строке и настройках панели. Если 9090 на компьютере занят,
например локальным предпросмотром, задайте другой `--port` при установке и
используйте его с обеих сторон SSH-туннеля. Не открывайте bootstrap-порт во внешнем firewall.
Корректность root-owned кода и системных ограничений нужна до публичного HTTPS.

## Ошибка установки

Откат останавливает только новые компоненты и выключает их автозапуск.
Если остановка подтверждена, новые файлы перемещаются в соседние скрытые
карантинные имена `.atlant-control-failed-...`; оригинальный VPN не трогается.
Перемещения внутри одного родителя работают и при разных mount points `/opt`,
`/etc` и `/var`. Ничего из карантина автоматически не удаляется. Журнал содержит
точные пути, включая приватные настройки и данные для восстановления.

При ошибке остановки фаза — `rollback-incomplete`: файлы остаются на местах,
чтобы не удалить код работающей службы. Проверяйте журнал перед повтором.
Созданный системный nologin-аккаунт сохраняется, а не удаляется автоматически.

Это обработка ошибок обычного запуска, **не законченная crash-recovery**:
отключение питания между шагами, повторная установка, обновление, удаление,
автоматический откат смены адреса самой панели ещё требуют реализации/приёмки.

## Что подтверждено тестами

Проверки пакета и ELF/архитектуры; в WSL под root — файловая транзакция в
отдельных временных каталогах, отказ старта, отказ остановки, неверный health,
неизменность VPN-конфига и отсутствие изменяющих вызовов его unit. systemctl и
health в транзакционных тестах контролируемые, не настоящие production-службы.
Ранее отдельно проверен настоящий запуск панели по HTTPS и Unix peer UID.
Успех этих тестов не объявляется приёмкой установки на VDS.
