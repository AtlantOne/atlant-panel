# Независимый агент сертификатов Atlant

Агент — отдельная программа `atlant-cert-agent`, не VPN-ядро и не веб-панель.
Он обслуживает только HTTP-01 на порту 80, выпускает сертификаты и публикует
закрытый файл состояния. Не вызывает systemctl, не меняет firewall и не
перезапускает VPN. HTTPS панели продолжает обслуживать Python-процесс,
подхватывая проверенную пару без перезапуска. REALITY не меняется.

Серверная основа и формы управления заданиями подключены к общей панели/CLI.
Полная установка и миграция действующего сервера ещё в работе.
Действующую службу этим кандидатом не заменяли.

## Режимы

- `acme-ip`: IP SAN и профиль CA `shortlived`.
- `acme-domain`: DNS SAN и стандартный профиль CA.
- Свои сертификаты не требуют агента: панель проверяет SAN/IP, срок и пару,
  затем перечитывает файлы каждые 30 секунд.

Продление определяется фактическими NotBefore/NotAfter: при оставшейся трети
срока сертификата, а не по жёсткому календарю «раз в 6/90 дней». Проверка
выполняется каждую минуту; после ошибки интервал повторов растёт от минуты
до часа. Предыдущий исправный сертификат не заменяется ошибочным ответом CA.
Не более двух выдач выполняются одновременно.

## Настройки задания

Пример схемы конфигурации агента (не конфигурация туннеля):

```json
{
  "state_dir": "/var/lib/atlant-control/certificates",
  "challenge_listen": ":80",
  "jobs": [{
    "id": "panel",
    "tls": {
      "mode": "acme-domain",
      "host": "panel.example.invalid",
      "cache_dir": "/var/lib/atlant-control/certificates/bundles/panel",
      "email": "",
      "accept_terms": false,
      "staging": true
    }
  }]
}
```

Замените адрес на свой домен/IP. `accept_terms` разрешено выставлять в true
только после принятия условий CA. По умолчанию пример выдачу не разрешает.
`--check` проверяет схему без запросов к CA и без открытия порта:

```sh
atlant-cert-agent --check --config /private/certificates.json
atlant-cert-agent --config /private/certificates.json
```

Каталоги и настройки закрытые; процесс запускается как `atlant-control`,
не root. Шаблон systemd находится в `management/systemd/atlant-cert-agent.service`.
Ему предоставлена только возможность открыть низкий порт, а запись ограничена
каталогом сертификатов. Пользователь/файлы должны быть подготовлены установкой;
самостоятельно шаблон не устанавливает приложение.

Файл `subscription.pem` содержит цепочку, ключ и контекст CA в одной атомарно
заменяемой записи. Имя сохранено для совместимости механизма подписок. Отдельные
задания обязаны иметь разные кэши и разные имена/IP. Панель и подписки на одном
IP могут использовать один сертификат; выпускать второй для того же IP не нужно.
Агент требует контекст нового формата: старый безметаданный кэш не считается
доказательством выбранного CA. Старый механизм подписок продолжает читать свои
старые кэши; это не автоматическая миграция службы.

После выдачи в настройках панели задаются `tls.mode`, `tls.host`, `tls.cache_dir`,
`tls.accept_terms`, `tls.staging`, а также
`certificate_agent.state_dir` и `certificate_agent.job_id`. `panel.origin` должен
быть HTTPS с тем же именем/IP. Переключение staging/production требует правильного
нового сертификата: панель отклоняет чужой контекст при старте и ротации.
Проверка `atlantctl paneltls` использует тот же валидатор, не обращаясь к VPN API.
Состояние агента старше трёх минут не выдаётся за подтверждение автопродления.

## Один порт 80 для нескольких HTTPS-служб

HTTP-01 обслуживает один брокер агента. Активные ответы сохраняются как
ограниченные по размеру файлы с привязкой к Host и token; после проверки они
удаляются, после аварии истекают через шесть минут. Чужой Host, POST, произвольный
путь и просроченный token получают 404. Число HTTP-соединений ограничено 64,
включая не отправившие заголовки; действуют короткие таймауты.

У механизма подписок есть `tls.challenge_dir`: при его явной настройке он
пользуется общим брокером, а не пытается занять порт 80 вторым слушателем.
Выдающие процессы и брокер должны работать под одним ограниченным пользователем.
Предпочтительная установка — выдача только агентом, а подпискам передаётся его
готовый bundle в режиме manual. Не меняйте пользователя существующего VPN и
права его базы ради этого до подготовленной миграции.

Если порт 80 уже занят другой панелью/веб-сервером, агент завершится с понятной
ошибкой и ничего не остановит. Перед включением нужен явный перенос HTTP-01
на один брокер либо настройка HTTP reverse proxy отдельно. Существующий сайт,
3x-ui и VPN автоматически не вытесняются.

## Доказательства и ограничения проверок

`go test ./certificates` в shared проверяет настоящие JWS/order/HTTP-01/CSR
запросы библиотеки ACME к локальной тестовой CA: IP/domain, два выпуска,
прямой и общий HTTP-01, перезапуск с bundle, отказ смены контекста CA,
изоляцию Host/token, истечение и очистку, блокировку параллельного издателя,
конфликт порта, отказ записи статуса и остановку агента.

Python-тесты проверяют настоящий локальный HTTPS-слушатель и две ротации,
имена/IP/срок/ключ, чтение автоматических bundle и недоступный/устаревший статус.
Это не выдача у публичной CA и не проверка входящего порта 80 с интернета.
Проверка публичной CA и установленных systemd-служб остаётся отдельным этапом.

## Управление без ручного JSON

В панели откройте «Настройки панели → Сертификаты»: создание IP/domain,
редактирование, прекращение продления и восстановление настроек доступны
через формы с подтверждением. Адрес и сертификат самой панели настраиваются
в «Адрес панели и HTTPS»: свой файл/ключ либо готовое задание агента. Проверяется
пара и имя; сохранение делает приватную копию настроек, не останавливает VPN
и применяется плановым перезапуском панели. panelset/panelbackups/panelrestore
и пункт консольного меню используют тот же код. Принудительное продление,
отзыв CA и автоматизированная установка ещё не закончены.

В терминале: `atlantctl menu → Сертификаты`. Те же операции доступны
прямыми командами `certjobs`, `certjobcreate`, `certjobset`, `certjobdelete`,
`certbackups`, `certrestore`; справка показывает параметры. Операции не требуют
работающего VPN API. Для авторитетной проверки нужен установленный бинарник
агента, указанный в `certificate_agent.binary` настроек Control.

Настройки находятся в `certificate_agent.state_dir/config.json`. Агент
проверяет изменения каждую секунду: валидный набор заменяет предыдущий после
остановки старых работников; ошибочная конфигурация оставляет прежние задания
и отражается в статусе. Изменение порта/каталога состояния требует явного
перезапуска. Допускается 0–16 заданий, один на каждое имя/IP. Ноль заданий
сохраняет брокер, не запуская выдачу.

Перед сохранением создаётся приватная копия настроек (не приватных ключей).
Восстановление также делает копию текущих настроек и проверяет ревизию.
Удаление задания сохраняет bundle и не является отзывом сертификата CA.
Параллельные редакторы защищены межпроцессной блокировкой.

Отдельный локальный интеграционный прогон:

```sh
ATLANT_CERT_AGENT_TEST_BINARY=/absolute/path/atlant-cert-agent \
  python3 -m unittest discover -s management -p 'test_*.py'
```

Он проверяет HTTP-подтверждения через настоящий `--check` бинарника, включая
дубликат имени, изменение, восстановление и удаление, но не вызывает CA
и не открывает порт 80. Публичная выдача проверяется отдельно.
