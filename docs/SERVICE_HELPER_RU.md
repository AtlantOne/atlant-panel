# Привилегированные операции Atlant Control

Панель не запускается от root и не получает произвольный sudo. Новый помощник
`management/atlant_service_helper.py` — отдельный Linux-процесс с узким набором
действий. Пока это проверенный транспорт и обработчики, а не уже установленная
служба на VDS. Полный установщик и приёмка реального systemd ещё в работе.

## Граница доступа

Панель/CLI подключаются только к `/run/atlant-control-helper/control.sock`.
Клиент проверяет, что серверный UID равен 0. Сервер через `SO_PEERCRED` допускает
только заданный UID панели и root. Права сокета 0660, каталог root:atlant-control
0750. Нельзя подставить пароль, HTTP-заголовок или имя пользователя вместо
ядром подтверждённого UID. Доступа по TCP нет.

Фиксированный набор: status/start/stop/restart одной службы Atlant,
configcheck/configsave четырёх разрешённых полей. Нельзя передать команду shell,
другую службу, путь конфигурации, API-secret, wire, приватный ключ или путь БД.
Одна операция выполняется одновременно; следующие отклоняются, а не становятся
поздними stop/restart после клиентского таймаута. Соединений не более четырёх,
вход ограничен 8 КиБ, ожидание запроса — тремя секундами.

Root-конфигурация `/etc/atlant-control/helper.json`, mode 0600:

```json
{
  "runtime_user": "atlant-control",
  "runtime_group": "atlant-control",
  "core_unit": "atlant_vpn.service",
  "core_config": "/root/config.json",
  "state_dir": "/var/lib/atlant-control-helper"
}
```

Само приложение и все импортируемые Python-модули в `/opt/atlant-control`
должны быть root-owned и не доступны runtime-пользователю на запись. Нельзя
запускать root-помощник непосредственно из пользовательской рабочей копии.
Файл ядра проверяется на root-владельца и отсутствие групповой записи/общего
доступа. Его прежние владелец, группа и права сохраняются при замене.

В приватной конфигурации клиента/панели указывается:

```json
"service_socket": "/run/atlant-control-helper/control.sock"
```

При наличии этой настройки sudo/старый исполняемый helper не используются.
Предыдущий путь оставлен для существующей установки до проверки миграции.
Панель сохраняет `NoNewPrivileges=true` и не получает права запуска команд
от root. systemd-шаблоны находятся в `management/systemd/`.

## Сохранение настроек ядра

Разрешены `sni`, `advertise_addr`, `up_mbps`, `down_mbps`. Проверяются типы,
границы и формат endpoint; JSON ключи протокола не переводятся. configcheck
возвращает ревизию действующего файла, configsave требует ту же ревизию.
Перед записью создаётся root-only полная копия конфига с секретами; она не
отправляется панели. Хранилище ограничено 200 копиями без автоматического удаления.

Сохранение не перезапускает VPN. Новый конфиг применяется отдельным явным
перезапуском. Аргументы ExecStart могут иметь приоритет над файлом; установщик
должен проверить фактически используемый путь и отсутствие перекрывающих флагов.
Не выдавать сохранение неиспользуемого файла за изменение работающего сервера.

Помощник ведёт собственный приватный журнал: время, разрешённая операция,
стадия и фиксированная служба; без тел запросов и ключей. Отказ записи начального
события не допускает изменяющую операцию. Настройки файла — не снимок SQLite:
восстановление общей квоты требует отдельной согласованной процедуры.

## Проверки и оставшаяся установка

Локальные тесты подтверждают allowlist, ревизию, сохранение секретов и бэкапа,
отказ записи и аудита, отсутствие очереди поздних операций. Настоящий Unix-сокет
в Ubuntu WSL проверяет UID вызывающего процесса и отклонение чужого UID.
В этих тестах systemctl заменён контролируемым исполнителем: работа службы
на настоящем сервере этими результатами не подтверждается.

Шаблоны проходят `systemd-analyze verify`. NTFS-копия может отображаться в WSL
как executable/world-writable; установленные unit-файлы должны иметь root:root
0644. Для конфига ядра в защищённом `/etc` установщик должен добавить точный
`ReadWritePaths` его каталога. Нужны также создание runtime-пользователя,
проверка root-owned исходников, права приватных состояний и плановый запуск.
Ничего из этого не выполняется автоматически простым импортом модулей.
